### מודל האבטחה

זה החלק החשוב. RLS פעיל על הטבלה, ויש בדיוק **מדיניות אחת**: הוספה.

```
INSERT  → מותר ל-anon   (כדי שהטופס הציבורי יעבוד)
SELECT  → אין מדיניות   ⇒ חסום לחלוטין
UPDATE  → אין מדיניות   ⇒ חסום לחלוטין
DELETE  → אין מדיניות   ⇒ חסום לחלוטין
```

המשמעות: גם מי שיפתח את קוד המקור של האתר וייקח את המפתח הציבורי — לא יוכל לשלוף אף פנייה.
קריאת הפניות עוברת **רק** דרך ה-Edge Function `admin-leads`, שבודקת את הסיסמה בצד שרת.

> אזהרת ה-linter על `WITH CHECK (true)` צפויה ותקינה — טופס יצירת קשר ציבורי חייב לאפשר הוספה אנונימית.

### Edge Function — `admin-leads`

`POST https://eequmwmeynpbasirhxqh.supabase.co/functions/v1/admin-leads`

```jsonc
// שליפת פניות
{ "password": "…" }
// עדכון סטטוס
{ "password": "…", "action": "set_status", "id": "<uuid>", "status": "contacted" }
```

- `verify_jwt: false` — הפונקציה מיישמת אימות משלה
- השוואת סיסמה בזמן קבוע + השהיית 600ms על כישלון, נגד ניחוש
- קוראת מהטבלה עם ה-service role key שנשאר בשרת

### הסיסמה

כרגע `1234`, כברירת מחדל בקוד ה-Edge Function.

**להחלפה לפני שהאתר עולה לאוויר:** Supabase Dashboard → Edge Functions → Secrets → משתנה `ADMIN_PASSWORD`.
ברגע שהוא מוגדר, הוא גובר על ברירת המחדל בלי לגעת בקוד.

הטבלה מכילה שמות, טלפונים ואימיילים של אנשים אמיתיים. `1234` הוא ארבע ספרות — ניתן לניחוש בשניות.
מומלץ מאוד להחליף לביטוי ארוך, ובהמשך לעבור ל-Supabase Auth עם משתמש אמיתי.
